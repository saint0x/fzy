# GPU Remaining Work

1. Harden the live `metal` execution path past the first real kernel launch. Kernel package consumption, launch submission, synchronous/asynchronous waits, and basic copy-style execution now run against the live Metal backend, but the remaining work is deeper production hardening: richer kernel shapes, better pipeline caching policy, launch diagnostics that pinpoint bad bindings/layouts, resource pressure handling, and stronger runtime cleanup/error reporting. Start in `crates/driver/src/pipeline/native_runtime_support/runtime_shim/gpu.rs`, `crates/driver/src/pipeline/gpu_kernel_metal.rs`, and the shared native backend lowering/runtime entrypoints.

2. Finish the stable backend-neutral launch packet and kernel identity contract across all backends. `kernel_ir` lowering, emitted package artifacts, Metal kernel descriptor generation, and the first live launch ABI now exist, but `spirv` / `nvptx` still need to consume the same contract, and the shared ABI still needs explicit versioning for argument layout classes, backend limits, and kernel capability flags. See `crates/kernel_ir/src/lib.rs`, `crates/driver/src/pipeline/policy_artifacts.rs`, `crates/driver/src/pipeline/gpu_backend.rs`, `crates/driver/src/pipeline/gpu_kernel_metal.rs`, and `crates/driver/src/pipeline.rs`.

3. Add scenario coverage for the unfinished runtime and backend behavior using Fozzy first. Existing coverage now exercises declared-backend truthfulness, host Metal lifecycle/upload/download, live Metal kernel launch/wait traces, replayed direct-launch artifacts, GPU borrow-region failures, kernel launch/barrier/access-mode verifier failures, richer multi-launch/error GPU trace evidence, async GPU wait policy artifacts/strict diagnostics, and replayed trace artifacts in `tests/gpu_backend_declared_build.pass.fozzy.json`, `tests/gpu_metal_host_lifecycle.pass.fozzy.json`, `tests/gpu_metal_upload_runtime.pass.fozzy.json`, `tests/gpu_metal_download_runtime.pass.fozzy.json`, `tests/gpu_trace_runtime.pass.fozzy.json`, `tests/gpu_trace_error_runtime.pass.fozzy.json`, `tests/compiler_gpu_borrow_regions.pass.fozzy.json`, `tests/compiler_gpu_kernel_contracts.pass.fozzy.json`, and `tests/compiler_gpu_async_runtime_policy.pass.fozzy.json`; what is still missing is broader live kernels (vector add / saxpy / relu), backend rejection cases for unsupported kernel shapes, and host-backed checks for every new runtime feature.

4. Add production gates once the live path exists. Before closing this file, the GPU stack still needs baseline kernels like vector add / saxpy / relu / image brightness, checks against unsupported fallback behavior or accidental scalarization, and stable diagnostics for host-from-device calls, unsupported device types, alias violations, barrier misuse, and backend lowering/runtime failures. Put that coverage in Fozzy scenarios and validate each finished chunk with `fozzy doctor --deep --scenario <scenario> --runs 5 --seed <seed> --json`, `fozzy test --det --strict <scenarios...> --json`, one recorded trace, `fozzy trace verify`, `fozzy replay`, and `fozzy ci`.
