# GPU Remaining Work

1. Harden the live `metal` execution path past the first real kernel launch. Kernel package consumption, launch submission, synchronous/asynchronous waits, and basic copy-style execution now run against the live Metal backend, but the remaining work is deeper production hardening: richer kernel shapes, better pipeline caching policy, launch diagnostics that pinpoint bad bindings/layouts, resource pressure handling, and stronger runtime cleanup/error reporting. Start in `crates/driver/src/pipeline/native_runtime_support/runtime_shim/gpu.rs`, `crates/driver/src/pipeline/gpu_kernel_metal.rs`, and the shared native backend lowering/runtime entrypoints.

2. Finish the stable backend-neutral launch packet and kernel identity contract across all backends. `kernel_ir` lowering, emitted package artifacts, Metal kernel descriptor generation, and the first live launch ABI now exist, but `spirv` / `nvptx` still need to consume the same contract, and the shared ABI still needs explicit versioning for argument layout classes, backend limits, and kernel capability flags. See `crates/kernel_ir/src/lib.rs`, `crates/driver/src/pipeline/policy_artifacts.rs`, `crates/driver/src/pipeline/gpu_backend.rs`, `crates/driver/src/pipeline/gpu_kernel_metal.rs`, and `crates/driver/src/pipeline.rs`.

3. Harden the GPU verifier around lifetimes, aliasing, and ABI checks. Live `GpuSlice` borrow-region enforcement now rejects freeing or reaccessing a buffer while a derived slice is still live, rejects competing live slices from the same owner, rejects aliased `GpuSlice` kernel-launch parameters that resolve to the same owner, and rejects `gpu.barrier` inside divergent control flow until uniformity analysis exists. Remaining work is `readonly` / `writeonly` style validation, broader kernel parameter capability/alias modes, broader device-safe aggregate support, and final ABI-shape validation for lowering. The relevant code is mainly in `crates/hir/src/lib.rs`, `crates/verifier/src/lib.rs`, and the GPU diagnostic path in `crates/driver/src/pipeline.rs`.

4. Keep incomplete backends truthful while wiring the shared architecture for `spirv` and `nvptx`. Those backends should stay non-executable until real codegen and runtime paths exist, but they should keep sharing the same backend selection, package, launch packet, and diagnostic surface as `metal`. Start with `crates/driver/src/pipeline/gpu_backend.rs` and the GPU pipeline/runtime split under `crates/driver/src/pipeline/`.

5. Expand trace coverage from lifecycle events to fuller replay-grade execution evidence. Real backend launches now emit launch/wait completion evidence on the Metal path, but missing pieces still include `gpu.error`, binding traces to kernel identity/dimensions/argument layout in a first-class way, and replay verification of resource lifetime across more than a single launch. The current trace hooks and native artifact logic live in `crates/driver/src/command/trace_native.rs`, `crates/driver/src/command.rs`, and the runtime shim.

6. Finish async/runtime policy for GPU events beyond the now-live wait surface. `gpu.wait` and `gpu.wait_async` execute on the Metal path, but cancellation behavior, deadline integration, and event lifetime policy for abandoned/pending launches are still undefined. The API surface is in `corelib/src/gpu.fzy`, with compiler/runtime support in `crates/hir/src/lib.rs`, `crates/runtime/src`, and the GPU runtime shim.

7. Add scenario coverage for the unfinished runtime and verifier behavior using Fozzy first. Existing coverage now exercises declared-backend truthfulness, host Metal lifecycle/upload/download, live Metal kernel launch/wait traces, replayed direct-launch artifacts, GPU borrow-region failures, and kernel launch/barrier verifier failures in `tests/gpu_backend_declared_build.pass.fozzy.json`, `tests/gpu_metal_host_lifecycle.pass.fozzy.json`, `tests/gpu_metal_upload_runtime.pass.fozzy.json`, `tests/gpu_metal_download_runtime.pass.fozzy.json`, `tests/gpu_trace_runtime.pass.fozzy.json`, `tests/compiler_gpu_borrow_regions.pass.fozzy.json`, and `tests/compiler_gpu_kernel_contracts.pass.fozzy.json`; what is still missing is broader live kernels (vector add / saxpy / relu), deeper parameter capability modes beyond the current no-alias rule, backend rejection cases for unsupported kernel shapes, and host-backed checks for every new runtime feature.

8. Add production gates once the live path exists. Before closing this file, the GPU stack still needs baseline kernels like vector add / saxpy / relu / image brightness, checks against unsupported fallback behavior or accidental scalarization, and stable diagnostics for host-from-device calls, unsupported device types, alias violations, barrier misuse, and backend lowering/runtime failures. Put that coverage in Fozzy scenarios and validate each finished chunk with `fozzy doctor --deep --scenario <scenario> --runs 5 --seed <seed> --json`, `fozzy test --det --strict <scenarios...> --json`, one recorded trace, `fozzy trace verify`, `fozzy replay`, and `fozzy ci`.
