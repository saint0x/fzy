# GPU Remaining Work

1. Finish real `metal` kernel execution. Host-side device selection, alloc/upload/download/free, slices, and trace plumbing already exist, but kernel package consumption, launch submission, `gpu.wait` / `gpu.wait_async`, and real completion still need to run against the live Metal path. Start in `crates/driver/src/pipeline/native_runtime_support/runtime_shim/gpu.rs`, `crates/driver/src/pipeline/native_runtime_support.rs`, `crates/runtime/src`, and the existing GPU entrypoints in `corelib/src/gpu.fzy`.

2. Add a stable backend-neutral launch packet and kernel identity contract. `kernel_ir` lowering and `.fz/gpu-kernel-package.json` / `.fz/gpu-kernel-package.md` already exist, but the runtime still needs one shared ABI for compiled kernels, launch dimensions, arguments, and backend limits. See `crates/kernel_ir/src/lib.rs`, `crates/driver/src/pipeline/policy_artifacts.rs`, `crates/driver/src/pipeline/gpu_backend.rs`, and `crates/driver/src/pipeline.rs`.

3. Harden the GPU verifier around lifetimes, aliasing, and ABI checks. Remaining work includes buffer/view lifetime rules, rejecting frees while derived slices are live, kernel parameter alias rules, `readonly` / `writeonly` style validation, barrier placement checks, broader device-safe aggregate support, and final ABI-shape validation for lowering. The relevant code is mainly in `crates/hir/src/lib.rs`, `crates/verifier/src/lib.rs`, and the GPU diagnostic path in `crates/driver/src/pipeline.rs`.

4. Keep incomplete backends truthful while wiring the shared architecture for `spirv` and `nvptx`. Those backends should stay non-executable until real codegen and runtime paths exist, but they should keep sharing the same backend selection, package, launch packet, and diagnostic surface as `metal`. Start with `crates/driver/src/pipeline/gpu_backend.rs` and the GPU pipeline/runtime split under `crates/driver/src/pipeline/`.

5. Expand trace coverage from lifecycle events to replay-grade execution evidence. Missing pieces include `gpu.error`, binding traces to real backend launches instead of only the current host lifecycle surface, and replay verification of kernel identity, dimensions, launch order, and resource lifetime. The current trace hooks and native artifact logic live in `crates/driver/src/command/trace_native.rs`, `crates/driver/src/command.rs`, and the runtime shim.

6. Finish async/runtime policy for GPU events. `gpu.wait` and `gpu.wait_async` are present, but cancellation behavior and deadline integration for pending launches/events are still undefined. The API surface is in `corelib/src/gpu.fzy`, with compiler/runtime support in `crates/hir/src/lib.rs`, `crates/runtime/src`, and the GPU runtime shim.

7. Add scenario coverage for the unfinished runtime and verifier behavior using Fozzy first. Existing coverage already exercises declared-backend diagnostics, host Metal lifecycle/upload/download, and trace emission in `tests/gpu_backend_declared_build.pass.fozzy.json`, `tests/gpu_metal_host_lifecycle.pass.fozzy.json`, `tests/gpu_metal_upload_runtime.pass.fozzy.json`, `tests/gpu_metal_download_runtime.pass.fozzy.json`, and `tests/gpu_trace_runtime.pass.fozzy.json`; what is still missing is real launch-and-copy success on the live backend, alias/barrier failures, backend rejection cases for unsupported kernels, replay validation, and host-backed checks for every new runtime feature.

8. Add production gates once the live path exists. Before closing this file, the GPU stack still needs baseline kernels like vector add / saxpy / relu / image brightness, checks against unsupported fallback behavior or accidental scalarization, and stable diagnostics for host-from-device calls, unsupported device types, alias violations, barrier misuse, and backend lowering/runtime failures. Put that coverage in Fozzy scenarios and validate each finished chunk with `fozzy doctor --deep --scenario <scenario> --runs 5 --seed <seed> --json`, `fozzy test --det --strict <scenarios...> --json`, one recorded trace, `fozzy trace verify`, `fozzy replay`, and `fozzy ci`.
